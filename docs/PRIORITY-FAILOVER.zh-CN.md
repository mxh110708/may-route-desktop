# 配置驱动的故障切换

## 按实际使用入口监测（2026-10-19 修正）

各地区的自定义顺序独立保存。编辑页的入口下拉仅用于查看和编辑，不决定哪些地区运行监测，也不会因为切换查看地区而清空已有顺序或产生待保存修改。可以先后修改多组，最后保存一次；保存欧洲后再查看美西，不需要再次保存。

监测读取核心连接事件中的实际分组链，而不是猜测默认出口、地区名称或节点所属关系。例如 AI 业务经过美西、网页经过 HK 时，两组同时独立检测、切换和恢复；只使用美西时，仅检测美西。直接引用具体节点而没有经过 selector 的连接，不会被误认为使用了某个组。

新业务、有效上传或下载、连接结束会刷新所属组的活动时间。业务结束或连接持续空闲后保留约 **60 秒**宽限，再暂停该组网络探测；后续业务自动恢复。内部节点探针及系统代理质量探测均排除，探针不能让闲置地区持续显示为在用。关闭功能、停止代理或切到 Direct 会暂停监测。

每组有自己的连续失败、备用成功、恢复稳定时间、手动首选和切换状态。所有地区共享最多三个节点探测槽位，其中备用最多占两个，优先安排当前节点和切换前复核，避免地区数增加时无限叠加并发。每个节点仍同时访问三个 HTTPS 目标，至少两个成功才算可用。一个地区全部不可用、另一个地区仍正常时，不以此触发整个代理的恢复重载。

运行策略只在当前配置内容、配置 ID 与接管模式匹配时即时更新。调整顺序、确认次数、间隔或关闭功能不重启核心。升级前运行实例可能只准备了单个组的探测入口，或启用功能时缺少入口：此时提示用户手动重载一次，之后切换地区不再需要重载。应用不会为应用设置而自动断开用户连接。

连接订阅每两秒更新流量增量，并接收核心的新建和关闭事件。只保留活动连接 ID 与分组标签、各组最近活动时间，不在桌面主进程额外保存完整地址、域名和连接表。断开或重置订阅时释放旧 ID，重连读取核心快照；无法读取使用状态时明确显示等待状态，不改为轮流探测所有地区。

## 图形界面（mxh.8 起）

概述页提供自动故障切换摘要卡片，仅显示运行状态、当前节点、目标组和待应用提示；点击整张卡片直接进入详情页，不会切换开关或重载代理。卡片可在“仪表项目”中隐藏或排序；旧布局首次升级会补充该入口，之后保留用户的隐藏选择。设置页原入口继续保留。

在设置首页点击与“应用、核心、远程控制”并列的 **自动故障切换** 入口，进入独立详情页；顶部返回按钮可回到设置首页。详情页按运行状态、入口与顺序、折叠的规则及高级参数分区。选择目标分组、启用自定义顺序后，拖动节点左侧手柄，按落点指示线释放即可排序；也可在手柄上使用键盘上下方向键，或使用上下按钮调整。拖动取消或在列表外释放不会改变顺序。可以移除不想参与的节点，再从下拉列表加入。未启用自定义顺序时，自动跟随组内排列。

高级参数默认折叠，时间以秒显示，保存时转换为配置文件的毫秒单位。面板显示当前运行节点、当前首选、自动监测／等待切回／直连暂停状态及本次应用运行中的最近自动切换。当前节点与首选相同时不重复显示长名称；运行状态来自正在运行的策略，不随未保存开关或待重载配置改变。

**保存配置不会重载代理**。所需探测入口已准备好时，保存后即时应用各组策略；只有界面提示缺少匹配探测入口时，才需要点击重载并确认短暂断连。代理未运行时不能通过此按钮隐式启动，下次正常启动会读取保存的设置。文件或当前配置在其他位置改变时，先刷新再保存，避免覆盖外部修改。

GUI 与下方文件使用同一份配置；首次打开面板也会创建默认配置文件。旧版桌面宿主或纯 Web 远程控制页不显示此本地设置面板。

应用不再识别 DMIT、VMISS 或 MoeCloud 前缀，也不再强制服务商优先级。

入口列表从应用当前选中的代理配置动态读取，不按分组名称或 `Entry` 后缀匹配。只有非空且所有成员均为实际代理节点的 selector 才可选；引用其他分组或包含 direct、block、DNS、urltest、缺失成员的业务、汇总或混合组均排除。界面、保存校验、运行时探针及缓存恢复共用这一规则。此规则基于配置结构，不推断名称的业务含义；请继续遵守业务组引用代理组的分层设计。

首次创建的 `group` 为空，只表示尚无编辑位置；监测是否启动由 `enabled`、实际流量和候选入口决定。各组默认沿用本组节点排列，不会把当前编辑组的顺序套用到别的地区。更换代理配置后，会对所有组清理失效节点，保留仍有效的自定义顺序；不会自动把原本排除的节点加入自定义列表。示例中的组名仅为示例，不是应用默认值。

首次启动代理时，应用在自己的数据目录创建 `priority-failover.json`。默认安装通常位于 `C:\ProgramData\may-route\priority-failover.json`；自定义数据目录时跟随实际位置。不会覆盖已有文件。它不是 `priority-runtime.json`，也不是 sing-box 权威配置的一部分。

完整示例见 [priority-failover.example.json](priority-failover.example.json)。旧版单组 `group + order` 自动迁移到对应组的 `groupOrders`。退出并重开应用不保证重新准备已运行核心的探测入口；配置不匹配时不会复用旧探测缓存。

## 常用操作

- **按组内顺序切换**：对应组不填写 `groupOrders`，或设置为空数组。沿用该 selector 的 `outbounds` 排列。修改原始代理配置的排列后仍需让核心载入该配置。
- **独立指定顺序**：在 `groupOrders` 中以精确 selector 名称为键，节点 tag 数组为值，例如 `{"美西入口": ["备用入口", "主入口"]}`。只监测列表内节点；未列出的组成员不参与该组自动切换。
- **查看别的分组**：界面切换下拉即可，各组保存的顺序与自定义开关分别还原。文件中的 `group` 和 `order` 保留为当前编辑组及旧版本兼容字段；`groupOrders` 中明确写出的对应项优先。
- **新增服务商**：把新代理节点加入目标组；空 `order` 会自动采用新组顺序，显式 `order` 则需一并添加名称。
- **关闭功能**：设置 `enabled: false` 并保存，立即停止监测；下次加载代理时不再创建探测入口。已运行的空闲回环入口无需为删除它们而强制重载。

## 参数

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `failureRounds` | 3 | 当前节点连续失败多少轮才考虑切换 |
| `backupSuccessRounds` | 2 | 备用节点需要连续成功的轮数 |
| `recoverySuccessRounds` | 3 | 首选恢复所需的连续成功轮数 |
| `recoveryStableMs` | 120000 | 切回前连续稳定时间，毫秒 |
| `failbackCooldownMs` | 60000 | 切回冷却时间，毫秒；当前备用也坏掉时仍可故障切换 |
| `probeTimeoutMs` | 8000 | 每个 HTTPS 探测超时，毫秒 |
| `healthyIntervalMs` | 30000 | 全部候选正常时，两轮之间等待时间 |
| `failureIntervalMs` | 10000 | 存在不可用候选时的常规轮间等待时间；当前节点初次失败后的连续复核除外 |

当前节点使用独立探测通道，不等待备用探测完成；备用最多两个并发探测。当前节点第一次探测失败后，下一次会在上次完成约 1 秒后开始，连续复核直到达到 `failureRounds` 或当前节点恢复。每次仍需三个 HTTPS 目标中至少两个成功才算可用，备用节点仍需达到 `backupSuccessRounds`，并显式跳过当前节点；若达到失败次数却没有可用备用，则退回 `failureIntervalMs`，避免持续高频探测。这个 1 秒是探测间等待，不包括探测本身的耗时。

连续探测次数允许 1–20；稳定和冷却时间允许 10 秒–1 小时；探测超时允许 1–60 秒；常规探测间等待允许 5 秒–10 分钟。轮询唤醒可能额外增加约 1 秒；探测耗时和备用就绪时间也影响实际切换延迟。睡眠或长时间断采样不会被算作持续恢复。

仍只选择真正的代理节点，不将 DIRECT、block、DNS 出站或嵌套选择组作为自动备用。每轮三个 HTTPS 目标中至少两个成功才算可用；单个目标失败、慢但成功的请求不会直接触发切换。全部不可用时保持当前选择，不自动直连。

手动选中参与自动切换的节点会把它设为**当前首选**，而不是暂停监测。当前首选故障时按配置顺序选择健康备用；它连续稳定恢复后再切回。手动首选写入运行快照和健康日志，即使改选恰好发生在一轮探测中也会记录；自动切换不会覆盖它，自动重载也会保留它。

重载代理或重启桌面程序时，只要当前代理配置和分组仍匹配，就继续使用保存的手动首选。旧版只保存暂停状态的运行快照会迁移为当前已选入口。若手动选中的节点已从自定义顺序移除，它没有独立探针，界面会提示不受自动切换监测；请把它重新加入顺序。健康守护在这种情况下可以执行整体代理重载，不会无限让步给不能监测当前节点的切换器。

配置文件错误会明确报错，不会默默恢复成旧的固定服务商顺序。桌面应用需保持运行（可留在托盘）。日志规则与 mxh.6 相同。
