# 多地区按实际使用监测：修复与验证

日期：2026-10-19。此记录随 1.14.2-mxh.18 发布，记录源码修复及隔离验证范围。

2026-10-20 发现通过落地出站的 `detour` 使用入口时，核心 selector 链并不包含该入口，旧识别会遗漏实际业务。当前源码已补充显式 detour 投影，并将概述卡片改为按实际监测组纵向展示；后续修正与验证见[入口识别说明](MONITORED-ENTRY-DETOURS-2026-10-20.zh-CN.md)。

## 原因与行为

旧版只保存一组 `group + order`，界面切换组时直接清空 `order` 并关闭自定义开关；运行策略同样只有一组，保存新组会覆盖原组。现在将各组顺序保存到 `groupOrders`，编辑位置与运行监测分离。保存一次保留所有组，切换查看地区不产生修改；有效运行配置直接更新策略，不隐式重载核心。

核心连接事件提供真实经过的 selector 链。只监测业务使用的组，多个地区同时有业务时并行管理各组，结束或空闲约 60 秒后暂停该组。内部节点探测按 inbound 排除；系统代理质量探测在写 CONNECT 前记录自身源端口并排除。裸节点引用不猜测为组使用。初次连接失败也能从核心路由后的连接事件识别到使用组。

每组分别保留手动首选、自动备用、失败确认和恢复状态。切换 RPC 回复超时但后来确认已切换时，仍保留原首选；不同组的自动切换不会互相作废。共用最多三个节点探测槽位，备用最多两个；旧上下文排队探测作废，在途探测由已有超时收敛。局部地区故障不会重启仍在服务其他健康地区的核心。

代理配置替换会对所有组清理旧节点，保留有效自定义子集；原子保存、配置内容修订检查、外部修改冲突保护继续保留。旧运行核心缺少多组探测入口时提示手动重载一次，准备完成后，地区切换与顺序保存均无需再次重载。

## 验证结果

- 主进程回归：173 项通过，含多组持久化、配置替换、活动归属、探测排除、并发限制、独立切换、恢复及 RPC 竞态；组名键的排列变化或跟随默认顺序不会误报需要再次保存。概述投影另验证实际监测组不受编辑组影响。
- Dashboard：19 个测试文件、112 项通过，含跨组草稿、保存后切回、多组状态摘要及卡片的实际组与对应节点展示；ESLint 与 CSS 检查通过。
- 打包隔离和延迟加载审计：9 项通过；TypeScript 类型检查、Electron Vite 正式构建通过。
- 真实编辑组件：隐藏隔离 Electron 窗口验证美西→欧洲→美西、自定义开关还原、跨组未保存修改、一次保存两组、切回无需重复保存、重开页保留顺序；一次保存，零次核心重载。该测试加入 Windows CI。
- 真实核心：从当前 `4f5df650c` 源码构建测试专用 RPC 夹具，直接使用未改动的 `daemon.StartedService`、连接事件和路由实现。临时回环代理产生 `w → West`、`h → HK` 分组链；节点探针和标记的系统质量探针不产生业务活动。返回 502 的第三组首次失败连接也识别到 `Europe`。该夹具不暴露系统代理控制，也不使用已安装守护进程。

测试均使用合成配置和独立数据目录，没有切换现用系统代理或 TUN，也没有安装或更新应用。

## 复现入口

桌面源码根目录：

```powershell
pnpm test:system-proxy-recovery
pnpm test:priority-editor:electron
pnpm typecheck
pnpm -C dashboard test
pnpm -C dashboard lint
pnpm -C dashboard lint:css
pnpm build
```

真实核心流量测试需要先构建专用夹具。在同级核心源码目录执行以下命令，路径按实际源码位置替换：

```powershell
go build -tags with_clash_api -o <隔离目录>/priority-core-fixture.exe <桌面源码>/scripts/priorityRuntimeFixture/main.go
```

然后回到桌面源码运行：

```powershell
pnpm exec tsx scripts/testPriorityActivityRuntime.ts <隔离目录>/priority-core-fixture.exe
```

夹具只接受回环监听和独立目录，结束后关闭自身进程及测试连接。结果通过临时目录的 JSON 文件记录，避免 Electron 测试向已关闭管道输出造成 EPIPE 弹窗。该二进制仅供测试，禁止作为发行版守护进程使用。
