# 第三轮内存优化与 Clash Verge 对照（2026-10-18）

> 2026-10-19 补测更正：本文基于 Windows 累计进程时间的 CPU 百分比保留为历史记录，不再用于证明改善或回退幅度。周期计数与 GPU 跟踪见 [CPU 计时复核](GPU-MEASUREMENT-2026-10-19.zh-CN.md)；内存、功能及调用次数分别判断。

本轮基线为已正式发布的 May Route `1.14.2-mxh.15`，改动随 `1.14.2-mxh.16` 发布。内存优先，CPU 次之；不通过中断代理、清空连接历史、关闭终端、丢失草稿或压缩 Windows 工作集降低读数。

## 参考来源和实际采样

本机 Clash Verge 文件版本为 `2.5.8`。检查同版本官方源码，提交 `4337bd85758d54d7b9044b2da3c9ac1176eae1f3`，没有修改、启动或控制 Clash：

- [`core/lightweight.rs`](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.8/src-tauri/src/core/lightweight.rs)：进入轻量模式调用 `WindowManager::destroy_main_window`，退出时重新创建窗口。
- [`utils/window_manager.rs`](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.8/src-tauri/src/utils/window_manager.rs)：销毁主 WebView 窗口，而非仅暂停网页计时器。
- [`Cargo.toml`](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.8/src-tauri/Cargo.toml)：宿主采用 Rust/Tauri，和 Route 的 Electron/Node 宿主不同。

用户打开 Clash 前台、未启用代理接管后，沿父子进程关系只读采样了一次。其主程序私有工作集约 14.23 MiB，加上属于它的 WebView2 主进程、渲染、GPU、utility 和 crashpad 子进程，合计约 161.56 MiB。另外存在约 59.81 MiB 的 Mihomo 进程、1.75 MiB 的服务进程和对应控制台进程。代理开关状态由用户提供；这里只确认进程存在，没有据此判断其转发状态。

因此主程序低于 20 MiB、整个前台客户端低于 20 MiB、关闭 WebView 后的轻量模式是不同口径。该单次采样不能证明长期上限，也不能把当前安装的 Route mxh.13 与不同运行状态的 Clash 直接排名。本轮不声称已把完整 Route 降到 20 MiB。

## 实际改动

1. **移除 Windows 的 Linux 依赖常驻。** 原 `tray.ts` 顶层导入 `x11Tray.ts`，使 Windows 同样加载 `dbus-next`。现在仅 X11 路径异步导入；Windows 托盘仍使用原生级联菜单。初始化期间关闭、重新开启托盘，通过代次检查避免旧任务重新创建已关闭的托盘。Linux D-Bus 失败时保留 Electron 托盘回退。实际构建的 `main-loading.json` 验证 Linux 托盘留在独立块，不在主入口的静态依赖图中。
2. **按需加载不常用页面。** 设置、网络测试、Tailscale、USB/IP、OpenConnect、OpenVPN、报告和相关错误/端口页面首次访问时才加载。代码、样式仍随包内置，离线可用；活动页面没有因隐藏被卸载。主内容加载边界保留导航壳，终端和 Markdown 沿用已有独立加载边界。构建审计检查缺失模块及间接共享块回流。
3. **后台连接数据与重绘分开。** 打开的连接页仍收集有界历史，不停止其不可可靠回放的流。隐藏时取消待发通知，后续只更新数据；恢复时通知一次最新快照，避免每批连接事件生成隐藏的 React 树。没有降低记录上限或删除历史。
4. **释放不用的可重建缓存。** 最后一个使用者离开出站、Tailscale 或 USB/IP 页面时释放其权威快照，返回时由服务器重建。仍有人使用时不释放。配置模式生成只合并同时进行的请求，完成后不再长期缓存整份原始 JSON；编辑器保留自己需要的解析结果，校验、补全和草稿不受影响。

没有照搬“后台立即销毁主界面”：这需要单独处理未保存输入、连接记录、活动终端和窗口恢复。本轮保留这些状态，不以破坏会话换取轻量模式数字。

## 验证方法

对发布前保存的 mxh.15 源码和本轮源码使用相同 Electron 43.4.1、同一 mxh.15 认证辅助进程、真实界面/IPC 和独立 StartedService 实例，交替运行停止/运行、前台/后台四种状态，各两轮；第二轮反转顺序。两侧均启用 mxh.15 已有的隐藏订阅暂停及停止后台辅助进程释放机制。

测试宿主额外导入实际托盘模块，确认基线加载 25 个 D-Bus 模块、本轮为 0；不弹出真实托盘菜单。运行场景持续经测试自己的回环 mixed 端口传输 64 KiB 数据并验证 SHA-256。未调用正式系统代理/TUN 开关或用户的服务。所有窗口始终隐藏，前台由文档可见性模拟；硬件加速两侧同样关闭。

每次配置处理后等待 22 秒，再采集三个进程树私有工作集、提交内存和累计 CPU 样本。V8 在这些采样之间存在明显回收波动；启动峰值和末次样本分开看，不能把首次较低读数当作稳定收益。测试不加载真实用户规则，也不等同正式安装实例或 Clash 跑分。

四种概述页状态的每轮末次私有工作集取两轮中位数如下。该列比启动期间的全样本中位数更适合判断稳定后的差距，但仍只有两轮，不代表长期上限。

| 状态 | mxh.15（MiB） | 本轮（MiB） | CPU：基线 → 本轮 |
| --- | ---: | ---: | ---: |
| 停止，前台 | 114.03 | 114.94 | 0.48% → 0.40% |
| 停止，后台 | 101.51 | 99.12 | 0.40% → 0.16% |
| 运行，前台 | 142.39 | 142.41 | 3.65% → 2.95% |
| 运行，后台 | 137.01 | 140.74 | 1.90% → 1.66% |

**普通概述页没有得到一致、显著的稳定内存下降。** 停止后台约少 2.39 MiB，而运行后台约多 3.73 MiB；这些小差值和 V8 回收波动共存，不能宣传为全部场景的内存优化，也没有达到 20 MiB。CPU 为采样区间累计进程 CPU 差值，以一个逻辑核心为 100%，包含测试数据发生器；不是任务管理器整机百分比。

### 后台连接历史专项

另用相同的真实核心和界面测量连接页：选择显示全部历史，前台先收集约 100 条记录，隐藏后每 20 毫秒发起一次真实回环 HTTP 传输，继续保留最多 1000 条关闭记录。两边使用相同负载、同样的上限，反转顺序各两轮。该负载明显高于普通空闲场景，用来验证隐藏列表的分配和重绘开销。

| 指标 | mxh.15 | 本轮 |
| --- | ---: | ---: |
| 六个样本私有工作集中位数（MiB） | 535.48 | 193.18 |
| 私有工作集样本范围（MiB） | 318.34–822.68 | 189.23–198.00 |
| 每轮末次提交内存中位数（MiB） | 700.77 | 320.32 |
| 区间 CPU（单核心口径） | 106.82% | 19.26% |
| 隐藏时保存的记录数，两轮 | 1000 / 1000 | 1000 / 1000 |
| 恢复可见后显示行数，两轮 | 500 / 500 | 500 / 500 |

本轮后台只保留隐藏前约 100 行的既有 DOM，继续在数据层收集 1000 条记录；恢复后显示与基线相同的 500 行，没有裁剪历史。该压力场景的样本中位数约少 64%，但基线本身波动很大，不能推广成全应用日常固定降幅。恢复时会一次性补齐列表；该场景恢复后的格式化 RPC 约 55–80 毫秒，基线约 7–18 毫秒，不宣称绝对零恢复成本。

四状态运行、连接页专项及正常使用验证累计经自有代理传输并逐次校验 582,483,968 字节，没有传输失败。原始记录、构建和测量脚本在工作区 `.codex-tmp/route-performance-pass3-20261018`，不打入安装包。

## 正常使用验收

148 项桌面 Node 测试、88 项界面测试、TypeScript、界面 lint 和生产代码构建通过。实际主入口不加载 D-Bus，所有新增延迟页面均存在于生产输出；正式 Windows 安装包沿用已有签名身份，发布资产附 SHA-256 校验文件。Linux 托盘的异步分支经过代码检查和构建依赖审计，未在真实 Linux 桌面重测 D-Bus 会话。

始终隐藏的真实 Chromium 界面验证通过：更新地址未保存草稿保留，GFM 发布说明/外链/表情/转义保留，终端输入输出正常，隐藏与主题切换没有重建活动终端，离开页面才关闭终端，原始文楷及导入字体真实解码，迟到字体清理，日志暂停/恢复正常。终端网络使用合成传输，不冒充真实 SSH 网络验收。

连接流新增回归覆盖隐藏期间 1000 条事件保留、零通知、恢复后一次通知，以及共享缓存只在最后订阅者离开后释放。真实核心的连接历史、活动长连接、日志补回、停止/启动、节点选择和后续传输另作隔离验收并通过。没有操作鼠标、切换正式网络或替换用户当前安装。
