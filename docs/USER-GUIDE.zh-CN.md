# May Route 使用手册

适用：Windows x64，文档基线 1.14.2-may.27。[英文版](USER-GUIDE.en.md)提供相同操作顺序的说明。应用状态、配置文件与真实网络是三个不同证据来源。

## 安装、更新与数据

从本仓库 Release 下载 Windows 安装器并核对校验信息。正式更新限定 May 来源、匹配版本与安装器名称，并由服务检查签名身份；不因下载走代理就放宽校验。现有安装沿用记录的位置，不建议将源码构建目录当作长期安装位置。

安装器会处理应用和守护数据归属。卸载时可选择保留或移除数据，默认保留；不要用清理工具误删后又把旧快捷方式当成有效安装。重新安装前核对已有标记和数据目录，不能为了通过安装覆盖来源不明的非空目录。

应用数据包含配置、设置、主机／核心状态、字体和日志。界面的打开数据目录入口比猜测固定路径可靠，尤其自定义过安装或数据位置时。卸载、删除配置和停止代理不是同一件事；保留的资料可能含可直接连接的秘密。

## 导入和启动

1. 准备受信 sing-box 配置，检查来源、节点认证、DNS、路由和所需地址族。配置不应包含无意启用的直连回退。
2. 在配置界面添加／导入并选为当前配置。远程来源、外部权威文件及应用内部运行副本要分清；导入不是将所有来源改到同一个路径。
3. 查看代理组，选择需要的入口与落地。节点名称不能代替实际服务身份。
4. 启动服务，确认当前配置加载成功。解析通过不证明出口可达，单次测速也不证明长时间业务质量。
5. 选择接管方式和路由模式，再用自己的业务验证规则命中与连接链。

由 Deploy 生成配置时，导出成功只表示文件写入；Route 仍需明确加载或更新它。避免直接修改其他客户端 AppData 中的运行副本。

## 两类模式

| 设置 | 决定什么 | 注意 |
| --- | --- | --- |
| 系统代理 | 使用 Windows 代理设置的应用进入本地代理 | 部分程序忽略系统代理，终端／下载工具需检查实际支持。 |
| TUN | 通过虚拟网络接口接管符合配置的流量 | 不代表所有平台／程序都无条件兼容；只在明确需要时开启。 |
| 规则 | 按配置规则选择出站 | 检查域名、重定向、规则顺序与业务组选择。 |
| 全局 | 按全局路径处理已接管请求 | 不会让原本未被接管的程序自动使用系统代理。 |
| 直连 | 代理配置按直连模式处理 | 与「完全停止服务」或「退出应用」不同。 |

不要同时让 Route 与 Clash 等软件争用系统代理或 TUN。检查当前 Windows 端点和应用状态再决定谁接管；日常只读排错不应随意切换系统设置。

## 规则、学术资源与校园授权

规则模式失败而全局成功，先确认请求确实被接管、实际域名及重定向链、命中规则和选择组。AI 交互、模型／数据集资源、学术数据库与国内／校园身份站点应有不同分类；某个关键词涉及 AI 不代表应全部放进 AI Services。

学校购买的数据库可能按校园出口授权。在 Academic Research 等对应组选择 DIRECT，并核对学校身份域名及下载域名的实际优先级。DIRECT 只沿用本机网络，校外不能因此取得校园出口；需要学校 VPN／认证时按学校要求连接。不要因一个下载失败就关闭全部证书或改成永久全局。

## 自动故障切换

在设置中进入「自动故障切换」。状态区展示实际正在监测的入口；下方下拉只查看和编辑某一组，记住上次编辑选择，不决定运行地区。

1. 为实际入口 selector 检查组内代理节点，自定义顺序按组保存。未设自定义时沿用该组配置顺序；显式顺序只包含愿意参与切换的节点。
2. 依次编辑多个地区后可保存一次；查看另一组不应清空前组顺序或要求重复保存未改变的设置。
3. 在「高延迟切换」核对明确地区预设或手工上限。填 0／留空表示该组仅连通性检测；恢复地区默认与关闭该组上限是不同操作。
4. 手动选择参与监测的节点会把它设为当前首选。故障后选择健康备用，首选满足恢复与稳定时间后切回。选到不在顺序内的节点时可能不受该组自动监测。
5. 业务实际经过一个组就监测一个，多个组则各自监测；空闲约一分钟后停止对应探测。直接引用具体节点但未经过 selector，不能凭成员关系算作使用某组。

默认当前节点连续失败 3 轮、备用成功 2 轮、首选恢复 3 轮且稳定 120 秒、切回冷却 60 秒。当前不可达首次失败后约 1 秒间隔复核，高延迟异常约 5 秒复核；这些是两次完成／开始之间的等待，不含请求耗时，不能承诺固定几秒内切换。

探测有三个 HTTPS 目标，至少两个成功，分别检查响应阶段与完整请求耗时。高延迟连续确认和有限短窗反复异常都会考虑，备用需低于对应上限 80% 并在切换前复核。所有节点一起异常则保持当前选择，不自动 DIRECT。详细地区表、参数范围、短窗及重载条件见[专项说明](PRIORITY-FAILOVER.zh-CN.md)。

首次打开先恢复监测与配置状态，再判断真实缺失；等待初始化、等待流量和需要重载是不同状态。只有已经确定运行配置缺少必要探测入口时才应提示重载。不能为了消除等待提示而反复重载正在使用的代理。

## 系统代理保持

功能区分本地 CONNECT 健康与 Windows 实际代理归属。正常状态下不重复写相同且健康的系统代理值；预期端点被关闭会有限确认后恢复，外来端点或 PAC 则停止争抢并提示。

Direct 和停止服务不做同样的代理探测。真正请求失败、设置被关闭、端口归属改变和其他代理接管有不同处理。看到暂停恢复通知时先检查实际所有者和健康日志，不通过反复开关 Clash 来强迫重夺控制。专项故障见[排错手册](TROUBLESHOOTING.zh-CN.md)。

## 托盘、窗口与字体

Windows 托盘左键单击显示／恢复主界面，并收起旧菜单；右键打开原生菜单，子菜单悬停展开。系统代理、TUN、配置、节点及路由操作复用相同后端。窗口隐藏不等于代理停止；查看关闭窗口设置后再决定退出方式。

仅支持简中和英文。原字体为默认，可选内置霞鹜文楷或导入合规 TTF／OTF；字体复制到应用数据，不安装到 Windows。原生 Windows 菜单使用系统菜单字体。字体文件最大 32 MiB，缺失或不支持会回退默认。

## 更新连接与取消

在「设置 → 应用 → 更新」的更新连接中保存地址。留空／恢复直连表示更新器不主动使用应用层代理；系统 TUN 等底层接管仍可能影响路径。支持不带认证的 HTTP、HTTPS、SOCKS5 代理，不能填写订阅或镜像 URL。

检查和下载均使用已保存的更新连接。指定代理失败不会静默转直连；指向 Route 自身时核心必须正常运行。下载期间可取消，等待流关闭与部分文件清理；安装器已接管后由安装过程处理。细节见[更新连接](UPDATE-CONNECTION.zh-CN.md)。

## 后台资源与日志

隐藏界面暂停可重放的读取、时钟与绘制，返回后读取当前状态。运行中的代理、日志归档、故障切换和健康保持继续；必要连接历史持续接收有界事件。停止代理且全部窗口隐藏等条件满足时可按需释放应用工作进程，恢复使用时重新连接。

不要定期清工作集、强制 GC、停止代理或缩减必要历史来制造任务管理器的低瞬时数字。比较需区分代理运行／停止、前台／后台、活动页面和相同流量，分别看各进程及一段时间的 CPU／内存。

`core-runtime.log` 与 `system-proxy-health.log` 位于应用数据目录，分别保留有限轮转文件（10 MiB／份，5 份）。日志可能含私人节点或目标信息，分享前脱敏，保留准确时间、状态和错误类别。
