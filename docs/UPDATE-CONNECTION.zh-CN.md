# 应用更新代理

在“设置 → 应用 → 更新”下展开“更新连接”，填写代理地址并保存。该设置在重启后保留，自动检查更新、手动检查和安装包下载均使用它。

- 留空保存或点击“恢复直连”，应用更新直接连接。
- 接受 `http://127.0.0.1:2080`、`https://proxy.example:443`、`socks5://127.0.0.1:1080` 等地址，支持 IPv6 代理地址，例如 `http://[::1]:2080`。
- 省略端口时，HTTP、HTTPS、SOCKS5 分别使用 80、443、1080；不接受用户名、密码、路径、查询参数、片段或代理规则列表。
- 更新进行期间不能修改连接设置。填写后需点击“保存”；输入无效时保留已保存的设置。
- 指定代理不可用时本次请求报错，不自动改用直连。若指向 Route 自身代理端口，该代理服务需保持运行；核心尚未启动时，启动自动检查可能失败，可稍后手动检查。

更新连接使用独立的内存网络会话，不设置系统代理、不修改核心配置，不与订阅、规则集下载或日常代理请求共用连接设置。留空的“直连”仅表示不主动使用应用层代理；操作系统级 TUN 或外部网络路由仍可能接管流量。

更新源仍限定为既有正式发布通道，安装包仍经过原有文件大小、版本和签名检查。代理地址是连接方式，不是 GitHub 镜像或更新源地址。不会因代理报错而跳过校验。

开发验证：`pnpm test:update-source` 覆盖地址校验、直连/代理配置、失败处理和连接串行生命周期；`pnpm test:update-connection:electron` 使用真实 Electron 网络栈与临时本地 HTTP、HTTPS、SOCKS5 代理，验证版本查询、重定向、流式下载、代理失败及恢复直连。后者需要 Electron 运行文件、OpenSSL；Linux 还需图形显示环境，可使用 `xvfb-run -a pnpm test:update-connection:electron`。测试证书仅在测试会话中临时信任，测试不启动 Route 核心，也不修改系统代理。
