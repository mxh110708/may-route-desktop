版本归档：经后续逐项复核保留的改动收入 `1.14.2-mxh.17`，见 [发布说明](RELEASE-1.14.2-mxh.17.zh-CN.md)。下文发布状态与实验结论记录的是当轮情况，最终保留判断以 [逐项实测](INDIVIDUAL-PERFORMANCE-2026-10-19.zh-CN.md) 为准。

> 2026-10-19 补测更正：本文基于 Windows 累计进程时间的 CPU 百分比保留为历史记录，不再用于证明改善或回退幅度。周期计数与 GPU 跟踪见 [CPU 计时复核](GPU-MEASUREMENT-2026-10-19.zh-CN.md)；内存、功能及调用次数分别判断。

本轮以已发布的 mxh.16 为基线，处理普通界面的常驻开销。内存优先，CPU 次之。现用安装未替换；以下是源码改进和隔离对照的结果。

## 实际改动

### 文楷按需加载，保留完整覆盖

原先选择文楷会解码完整 TTF。现在基于同一原始字体生成常用字符段及其余汉字范围的 WOFF2，界面首先准备常用段，出现其他字符时由浏览器读取相应的本地段。所有范围都随应用打包，覆盖并集与原字体相同，为 46,490 个字符；原始 TTF 和 OFL 仍保留，加载失败时用于恢复。

完整非汉字字符、韩文音节、变体关联字符保留在常用段。CSS 范围额外包括规范分解的组合输入，保证韩文字母等输入可以先由字体整形为原来支持的音节。常用段最后注册，使计数器和时钟优先匹配常用范围。定义模块也在选择文楷时才加载，使用默认字体不会执行这份范围表。

某一段失败后，共享一次完整字体恢复请求。成功后删除旧段的注册和引用，使用完整原字体。切换到其他字体后，迟到的失败不会重新加载整份文楷；旧加载失败也不会删除较新的同字体缓存。导入字体继续使用原始 TTF/OTF 字节及既有导入逻辑。

`dashboard/scripts/build-interface-font.py` 记录生成方法；使用 FontTools 4.55.3、Brotli 1.0.9。普通构建直接使用已生成的资产，不依赖 Python。需要更新原字体时可重新生成，再用 `--check` 核对原始 SHA-256、覆盖、映射、轮廓、指令和度量。清理只作用于旧 manifest 声明的同目录生成字体。

### 故障切换状态复用分析结果

概述页的状态刷新此前会反复构建运行配置、解析全部节点并传回编辑器列表。现在只保存当前一份分析投影，内容包含分组、策略和内容摘要，不保留原始配置文本。每次仍读取并哈希实际文件，缓存身份同时包含配置 ID、内容摘要、接管方式及策略版本；同长度替换和外部编辑也会重新分析。

概述页使用精简状态接口，刷新频率保持原样。状态相同则复用界面状态，编辑器仍可获得完整节点列表。恢复故障切换策略时也复用分析结果。节点识别使用集合查找；筛选、优先顺序和手动排除的含义保持一致。

## 四种状态对照

基线桌面提交为 `332e0bb4e2ef30769ebc41f89183c4a1a8dcc983`，dashboard 为 `ba9cc1649e02f068009f3423894a99027983a44c`。每种状态运行前后版本各两轮，第二轮反转顺序。相同 Electron 43.4.1、1280×800 窗口、完整文楷覆盖、硬件加速与合成配置；配置包含 32 个代理及 668 条路由规则，使用实际的配置状态计算与 IPC。

每轮准备界面后等待 18 秒，再采四次进程树私有工作集、提交内存及累计 CPU。下表为每格八个样本的中位数；CPU 由采样区间累计 CPU 增量计算，以一个逻辑核心为 100%。

| 状态 | mxh.16 私有工作集（MiB） | 本轮（MiB） | CPU：基线 → 本轮（单核心） |
| --- | ---: | ---: | ---: |
| 代理运行，前台 | 156.18 | 145.06 | 4.62% → 3.66% |
| 代理停止，前台 | 139.12 | 122.40 | 1.15% → 0.24% |
| 代理运行，后台 | 150.70 | 136.96 | 3.27% → 2.88% |
| 代理停止，后台 | 133.78 | 123.50 | 0.53% → 0.38% |

16 次运行共 64 个内存样本。运行场景合计经自有代理传输并逐次校验 95,027,200 字节，失败数为 0。每轮末次样本的两轮中位数也保留在 `summary.json`，与全部样本中位数方向一致。

本机有 24 个逻辑处理器；这里的 CPU 百分比包含测试数据发生器，不能直接当作任务管理器的整机百分比，也不外推成所有负载下的固定降幅。

这组结果是相同条件下的前后差异，不等于现用安装的任务管理器绝对值。原生窗口始终隐藏，前台由文档可见性模拟；后端为自己持有的回环 StartedService 实例。统计包括测试 Electron 及其代理后端，不包括正式 Windows 特权服务、认证 relay 和应用辅助进程。后台保持打开的界面，不靠销毁窗口得到低读数。

运行场景持续传输并逐次校验真实代理数据，使用测试自己的端口。配置替换后也通过实际状态接口核对旧节点消失。原始记录位于工作区 `.codex-tmp/route-performance-pass4-20261018/`，`summary.json` 保留两轮数据的汇总和测量边界。初次字体匹配顺序的对照另存于 `prior-font-order/`，不与最终数据混合。

短时间采样仍有 V8 回收和进程工作集波动，不代表长期上限。访问更多不同字符会增加已解码字体数据；本轮收益主要适用于文楷的常见界面内容。没有把字体文件压缩率或单项测试的差值当作整应用固定降幅。

## 正常使用与构建验收

字体原始覆盖检查已纳入 `test:interface-fonts`，生成文件逐个核对 SHA-256，并核对运行时范围声明。额外用真实 Chromium 分 182 页比较全部 46,490 个字符的像素；英文组合、中文、日文、韩文组合输入、变体字符及其他文字的测试串也核对像素和宽度。独立会话注入本地字体文件缺失，确认能恢复完整原字体并释放旧段。

真实界面验收覆盖更新地址草稿、发布说明格式与转义、日志暂停及恢复、内置和导入字体切换、迟到字体清理。活动终端保留同一会话并继续转发输入；离开页面时才按原有规则关闭。终端传输为合成实现，不作为真实 SSH 网络验收。

配置与策略回归覆盖同长度新配置替换、配置 ID/接管方式/策略版本变化、无效配置、不可变缓存及精简状态。后台连接历史、代理恢复、托盘行为和原有界面生命周期继续由现有测试覆盖。

155 项桌面 Node 测试和 95 项界面测试通过。最终检查记录见 `checks.json` 及各项日志；包括桌面和界面测试、TypeScript、JS/TS 与 CSS lint、安装数据恢复检查、生产构建和实际加载边界审计。字体范围定义、终端、Markdown 及不常用页面都必须保留为随包内置的延迟模块。
