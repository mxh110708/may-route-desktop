# Windows 原生级联托盘菜单

## 修正范围

1.14.2-mxh.11 的 Windows 托盘把左右键都绑定到弹出菜单，并使用点击切换页面的方式模拟子菜单，未遵循常见桌面菜单交互。本次将 Windows 托盘调整为原生级联菜单。

- 左键单击先收起菜单，再调用主界面现有显示/恢复逻辑。双击通知没有额外的重复激活处理。
- 右键手动弹出 Electron 原生菜单，不通过 `setContextMenu` 接管左右键事件。
- 路由模式、组、组内节点、配置、远程配置更新和更多操作均使用真正的 `submenu`。父项不绑定点击切换页面的操作；悬停、跨入子菜单、边缘翻转及键盘导航由平台菜单实现。
- 首页保留 10 个操作及分隔线。菜单字体由系统提供，主题跟随应用设置；主界面字体库不受影响。
- 原有配置、系统代理/TUN、服务启停、节点选择、测速和更新方法被直接复用。模式状态通过守护进程订阅缓存，弹出时不等待网络或本地 RPC。
- 每次弹出根据当前状态重新生成菜单。配置、连接或服务状态变化时关闭旧菜单；繁忙、服务过渡和断线时限制不可用操作。
- 节点、组和配置中的 `&` 转义为原生菜单中的字面字符，操作参数仍使用原始名称。
- Windows 不再预加载 React 托盘窗口。Linux 保留现有托盘实现。

## 验证

- 3 项真实事件注册回归：左键只显示主窗口；右键只打开菜单并传递锚点；双击通知不重复激活。
- 5 项菜单回归：各级父项均为原生子菜单且没有切页点击；名称转义不改变操作参数；动作与勾选对应；状态限制；新配置不保留旧节点。
- 独立 Electron 进程中使用实际 `Menu.buildFromTemplate` 和真实原生 `Menu`/`MenuItem` 对象，验证左右键注册、两级子菜单、10 个首页入口、模式/TUN 勾选、节点选择、远程更新、配置切换、导航路由、数据目录、重载、关闭连接及新配置刷新。
- 集成验证替换了托盘图标、菜单弹出与后端，没有创建 BrowserWindow、显示菜单、发送桌面输入或切换实际代理。样式主题通过原生 `nativeTheme` 的应用级设置验证。
- 遵守用户不操控鼠标的要求，没有执行物理悬停、点击或真实屏幕边缘翻转测试。平台级悬停交互由原生菜单提供；本次自动验证覆盖菜单结构和接线，不把事件模拟称为物理桌面实测。
