# 托盘紧凑菜单修正与验收

## 问题

1.14.2-mxh.10 套用了主界面的控件高度、分区标题和按钮组，又固定弹窗为 360 × 584 DIP。首页自然内容超过可用高度，需要滚动。此前功能测试没有把“所有首页操作完整可见”作为验收条件，未能发现这一问题。

## 实现

- 首页为 10 行普通菜单：概述、服务启停、路由模式、组、配置、系统代理、TUN、重新加载、更多、退出。
- 宽 244 DIP，普通行高 28 DIP，使用 13 px 菜单字号；原字体、内置与导入字体均沿用用户偏好。根菜单正常高度为 330 DIP，包含两侧和上下留白。
- 去掉大标题、状态副标题、切换大按钮及独立页脚。系统代理/TUN 使用勾选项，路由选项与维护入口移入子菜单。
- 配置、组和节点页面支持搜索；按内容计算高度，实际显示仍受图标避让区域与显示器工作区限制，足够长的列表才滚动。
- 尺寸按各区域自然高度、边框、内边距、外边距计算，不从被窗口限制后的高度反推。错误区和内容变化会重新计算，保留末行底部空间。
- 托盘显示前等待根菜单更新；隐藏窗口仍允许布局帧执行，避免显示准备停在被节流的动画帧上。关闭仍隐藏窗口。
- 尺寸 IPC 检查发起者确为当前托盘窗口，尺寸必须为有界整数。其他窗口和无效输入均拒绝。

## 验收

在独立用户目录中运行隐藏 Electron 窗口，没有操作用户鼠标、激活用户窗口或更改实际系统代理/TUN。窗口显示与焦点调用被测试替换，但执行实际托盘显示准备、尺寸 IPC、字体加载和偏好实现；代理后端使用合成数据。

| 检查 | 结果 |
| --- | --- |
| 100%、150%、200% 显示缩放 | 通过，实际 `devicePixelRatio` 分别为 1、1.5、2 |
| 原字体、文楷、导入字体 × 深浅色 × 三档缩放 | 18 组通过 |
| 正常首页 | 窗口 244 × 330 DIP，10 行全部可见，正文与页面均无溢出 |
| 底部空间 | 退出项下方保留空间，没有裁切或用隐藏溢出来掩盖内容 |
| 系统代理/TUN、路由模式 | 合成后端的变更与勾选状态通过 |
| 组与节点、配置切换、更多入口 | 通过，保留原后端操作 |
| 21 个代理组 | 按内容增高，在测试显示器可用空间内完整显示；回到首页恢复紧凑尺寸 |
| 长错误提示、服务停止与断线 | 首页仍完整显示，错误有界展示，不挤掉底部操作 |
| 子菜单方向键与返回 | 隐藏窗口 DOM 事件通过 |
| 显示前布局准备 | 通过，没有因隐藏窗口动画帧节流而挂起 |
| 非托盘发送者、NaN、超宽、负高及空尺寸 | 拒绝 |
| 图标避让、负坐标工作区及小屏内容尺寸 | 3 项布局测试通过 |

尚未通过物理桌面输入验证真实点击、失焦关闭和任务栏交互；遵守用户不操控鼠标的要求。自动化布局和菜单操作结果不代表生产网络已切换实测。
