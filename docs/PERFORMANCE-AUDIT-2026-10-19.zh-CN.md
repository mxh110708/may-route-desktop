版本归档：经后续逐项复核保留的改动收入 `1.14.2-mxh.17`，见 [发布说明](RELEASE-1.14.2-mxh.17.zh-CN.md)。下文发布状态记录的是当轮审查情况。

> 后续状态：逐项新实测已完成，最终依据和决定见 [逐项实测记录](INDIVIDUAL-PERFORMANCE-2026-10-19.zh-CN.md)。下文保留补测前的审查过程。GPU CPU 的旧计时异常已经定位，见 [计时复核](GPU-MEASUREMENT-2026-10-19.zh-CN.md)，不再作为未解决的源码回退问题。

按用户要求，复核正式发布于 mxh.15、mxh.16 的调优（含 mxh.14 阶段累计变更）及其后三轮未发布源码。验收通过不等于性能改善；不同基线、不同负载的收益不能相加。以下依据实际代码路径、保存的对照 JSON、构建依赖审计及功能回归作出决定。已发布部分的判断属于代码与既有证据复核，尚未逐项重新进行隔离性能对照，不能称作全部完成新一轮实测验收。

## 撤回与不采用

- **撤回本轮通用分段历史缓冲 `BoundedHistory`。** 连续显示日志的专项为 44.18→47.55 ms，未有正向性能贡献；未读取数组的专项虽改善，实际日志页每轮读取且隐藏时暂停订阅，尚未证明这种最佳情形代表正常使用。读出数组后同时保留页和数组也增加了存储形态与维护成本。恢复原有普通数组、3,000 条日志上限和 30 点曲线上限，保留旧快照不变与离页紧凑存储。
- **撤回曲线的额外快照类。** 交错四轮、每轮十万次读写的微基准显示新结构 13–23 ms、原数组 33–40 ms，但正常一秒一次、仅 30 点；单次亚微秒差距不足以证明正常使用收益。统一回到原数组，减少对象形态和维护分支，不宣称该回退本身节省多少内存。
- 页面编辑器/终端重复开关只是验证既有释放逻辑，不再将其写成新增优化收益。
- 之前实验中的全量展开环形缓存、WeakMap 快照元数据、低 Go 内存限额及降低并发均未进入最终代码，不需要再次回退。
- 未采用销毁后台主窗口、删减连接历史、裁剪 Windows 工作集、替换字体、降低代理并发等会改变使用体验或只美化读数的方案。

## 证据与结论边界

旧记录分别见 BACKGROUND、STARTUP、MEMORY、THIRD、RESIDENT、TWO-LANGUAGES 和 STREAM 对应性能文档，以及工作区 `.codex-tmp/route-*` 原始记录。本次已重新读取第三至第五轮汇总及本轮逐进程 CPU 样本，未用旧摘要代替所有当前证据。

本轮撤回前四状态结果混合，不能宣称全部常驻占用下降。运行前台 GPU CPU 增量偏高在补测中再次出现，不能简单归为单次离群值，更不能删掉该样本。该观测尚不能归因于某一源码改动；没有据此盲目关闭硬件加速或改变渲染行为。撤回后单独补测，保留原始记录，不覆盖原结果。

所有测试仍使用自有隔离回环服务、合成配置和隐藏窗口，不控制鼠标或现用系统代理/TUN。性能矩阵不是用户安装版绝对资源占用，也不保证任意机器、配置和运行时长都更低。

本次只修改源码和验收文档，未提交、打包、发布或替换现用安装。

## 撤回后复测

第 7、8 轮仅补测运行前台，顺序交错。基线单核心 CPU 为 3.34% / 3.81%，撤回后为 11.19% / 2.49%；优化侧 GPU 增量分别为 1,625 ms / 31.25 ms，基线为 109.375 ms / 62.5 ms。四次均零传输失败。可见撤回历史结构没有排除 GPU 异常，不能声称已找到它的原因或完成整应用性能验收。原始文件为 `baseline/optimized-running-foreground-7/8.json`。

这项未解决问题是发布前检查项。上述“保留”表示有明确的局部或其他正向贡献，不表示允许忽略整应用 CPU 回退；当前没有把该版本作为已完成性能验收的安装包发布。

源码回退后 107 项界面测试、TypeScript、lint、生产构建及加载审计通过。隐藏真实界面再次通过编辑器、终端、版本说明各 12 次开关，草稿保存/取消关闭、日志暂停恢复、字体切换、旧语言回退及后台终端会话保留均通过，无渲染错误。157 项桌面测试在本轮回退前已通过，本次未改变对应桌面实现。不同状态完整矩阵为回退前数据，不混用为回退后四状态结果。
