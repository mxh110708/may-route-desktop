# mxh.15 至 mxh.17 调优的逐项实测

发布归档：本次保留的源码改动随 `1.14.2-mxh.17` 提供，安装包与更新入口见 [发布说明](RELEASE-1.14.2-mxh.17.zh-CN.md)。下文“当前界面”指该版本的界面源码；测试阶段的“待发布”描述保留其时间背景。

## 结论与范围

本次重新执行实测，覆盖 mxh.15、mxh.16 已发布的调优及其后待发布源码。已发布改动均有明确的局部资源收益、减少工作量的收益或启动加载收益，保留。此前撤回的通用历史缓冲和曲线快照类继续撤回。

没有证据支持“每一轮、每一项、每一种状态都降低常驻内存”。尤其 mxh.15 到 mxh.16 的普通概述页没有一致的稳定内存改善；后台重绘、低频模块等必须按其对应场景判断。简中/英文收敛没有在本次单项实验中证明独立的常驻内存下降，保留依据是用户明确要求、加载量减少和维护范围缩小。

GPU 进程 CPU 大幅回退的旧结论由两套计时与线程跟踪重新核对，原因见 [GPU CPU 计时复核](GPU-MEASUREMENT-2026-10-19.zh-CN.md)。没有关闭硬件加速或忽略不利样本。

## 发布版本界面对照

分别从 Git 提取发布前 mxh.13 的 dashboard `69c7c31`、mxh.15 的 `79ece35`、mxh.16 的 `ba9cc16`，与当前工作区界面在**同一个隔离主进程宿主**运行。这样测量界面代码的差异；主进程和 Go worker 的变更另做下面的单项实验，不能将此表称作四份完整安装包的比较。

四状态各两轮，第二轮反转顺序。每次准备界面并等待 18 秒，再采四个私有工作集样本；每格八个样本取中位数，单位 MiB。

| 状态 | mxh.13 界面 | mxh.15 界面 | mxh.16 界面 | 当前界面 |
| --- | ---: | ---: | ---: | ---: |
| 停服、前台 | 138.78 | 135.00 | 135.36 | 122.46 |
| 停服、后台 | 137.32 | 136.64 | 134.72 | 117.78 |
| 运行、前台 | 158.63 | 159.67 | 155.77 | 147.31 |
| 运行、后台 | 165.48 | 149.62 | 150.19 | 136.77 |

mxh.15→mxh.16 的停服前台和运行后台中位数略升，不能写成所有状态都下降。当前界面与 mxh.16 在该条件下约少 8.5–16.9 MiB，不能换算成用户现用安装的固定降幅。用户之前任务管理器截图的上升是真实观察；未在那个时点抓取完整分配记录，无法仅凭本次隔离实验唯一还原其原因。

完成校准后的 Electron 进程树 CPU 如下，以一个逻辑核心为 100%，不含自有代理后端。CPU 统计与内存统计的进程范围不同，不能直接合成效率比。

| 状态 | mxh.13 界面 | mxh.15 界面 | mxh.16 界面 | 当前界面 |
| --- | ---: | ---: | ---: | ---: |
| 停服、前台 | 0.99% | 0.57% | 0.55% | 0.55% |

这些小幅 CPU 差值不单独作为保留或撤回的依据，专项工作量和对应负载更有解释力。

## 单项结果与决定

下表每项均使用本轮新执行的结果，不用旧文档的结论代替测量。函数级、对象保留级结果不等同于应用 RSS。Node 显式 GC 仅用于独立对象测量，没有加入产品；普通窗口矩阵不显式 GC、不裁剪工作集。

| 项目 | 本轮实测 | 代价与决定 |
| --- | --- | --- |
| 隐藏时暂停可重放订阅 | 实际界面采样区间状态更新 18→0，通知均为 0 | 单次 A/B 的私有工作集 132.83→137.17 MiB，没有证明独立内存下降；减少后台处理有效，保留 |
| 隐藏时暂停时钟/界面轮询 | 实际界面相同运行时段内概述读取总数 13→5；额外 8 次隐藏读取消失 | 单项内存 117.67→124.90 MiB，不宣称内存收益；减少无用途读取、避免堆叠请求，保留 |
| 停服时关闭后台组订阅 | 实际 `DaemonState` 类运行 3.2 秒，旧版停服组调用 1，当前 0；启动后正常恢复到 1 | 不裁剪运行时监控，保留 |
| 停服时移除故障切换调度 | 提取真实调度块，停服→运行→停服各 3.1 秒：旧版回调 3/3/3，当前 0/3/0；当前停服无计时器 | 减少无用途唤醒，保留 |
| 停服后台释放空闲 worker | 同一新版 worker，空闲保留约 13.06 MiB→退出后 0；两轮均确认旧 PID 退出并按需重建 | 首次格式化约 1.21→601.28 ms；仅停服后台且无在途工作时释放，保留并记录冷启动代价 |
| 配置处理后单次归还 Go 空闲堆 | 原版与堆回收版各两轮：空闲工作集中位数 25.56→13.30 MiB；再次格式化约 1.06→1.01 ms | 工作集随配置和 GC 波动，不保证固定 12 MiB；只作用应用 worker，保留 |
| 终端/Markdown 延迟加载 | 独立界面两轮：提前加载 126.84 MiB，按需加载 123.90 MiB；初始静态 JS 1,155,214→614,397 B | 首次访问加载本地模块；会话/草稿仍保留，保留 |
| 低频页面延迟加载 | 两轮：提前加载 124.53 MiB，按需加载 123.90 MiB，差值很小；初始 JS 728,302→614,397 B | 常驻收益不显著，加载量减少明确，保留 |
| 发布界面脚本压缩 | 相同当前源码：未压缩 129.76 MiB，压缩 119.06 MiB；初始 JS 1,361,491→614,397 B | 实测加载与保留量有收益，保留 |
| Windows 不加载 D-Bus | 独立 Node 新进程：省去 67 个传递模块、约 2 MiB 保留堆及约 107 ms 模块载入 | 是不需要的平台依赖成本，不当作全应用固定降幅；保留 |
| 后台连接收集与通知分离 | 高连接负载反转顺序各两轮：270.87→215.71 MiB；CPU 27.13%→16.13%；约 1,730 次隐藏通知→0；两侧均保留 1,000 条历史 | 前台恢复补绘，保留；不是通过减少历史取得收益 |
| 最后订阅者离页后释放可重建表 | 独立真实 `StreamStore`，10,000 条合成记录：约 2,286→21 KiB 保留堆，旧表行数 10,000→0 | 只用于可从权威快照重建的表；日志离线历史不清空，保留 |
| 日志恢复滚动后释放冻结副本 | 相同 3,000 条日志，冻结副本保留约 800 KiB，释放后约 401 KiB | 暂停内容不变，恢复后释放旧引用，保留 |
| 原始 schema 只合并在途请求 | 提取实际 host 方法，2.28 MB 合成 schema 连续访问四次：保留堆约 2,331→114 KiB | 请求次数 1→4，合成生成总耗时约 14→48 ms；编辑器自己仍保留解析对象。释放闲置原文有收益，保留 |
| 导入字体使用原字节视图 | 同一原始 25,575,676 B 字体：避免约 24.39 MiB 额外 ArrayBuffer；20 次转换约 188.45→0.09 ms | 不改变字节、偏移和长度，保留 |
| 文楷分段按需解码 | 仅还原字体加载器，其余当前功能相同：整份加载 137.79 MiB，分段 123.90 MiB | 使用更多字符会继续解码；完整覆盖和 TTF 回退仍保留，保留 |
| 故障切换投影缓存、集合识别和精简状态 | 同配置连续分析 100 次：32 节点约 89→2 ms，1,000 节点约 413→9 ms；集合识别在 1,000 节点约 76→32 ms。每次真实 UI 运行又核对同 ID 新配置节点替换 | 小节点集合的单项识别没有明显加速；缓存与减少传输有效，保留 |
| 简中/英文收敛 | 同源码恢复旧翻译与语言解析后，初始 JS 675,858 B；当前 614,397 B。独立 RSS 为旧 117.46、当前 119.06 MiB | 不宣称独立常驻内存下降；按明确功能要求、较小加载量及维护范围保留 |
| 连接增量快照与空帧复用 | 1,000 连接、更新 32 条、1,000 帧：27.25→4.02 ms，堆峰值增量 31.83→6.98 MiB；10,000 连接相同负载约 365.57→4.83 ms | 1,000 连接全量更新的 100 帧时间 6.16→8.55 ms，但峰值分配更低；内存优先下保留，记录 CPU 权衡 |
| 离页日志无损紧凑存储 | 3,000 条中文短日志，独立进程保留堆约 502→366 KiB，编码/恢复各约 0.64 ms | 收益仅约 0.13 MiB；大诊断文本跳过，断线历史保留，保留 |
| 字体管理与报告实现延迟加载 | 真实实现的隔离分块测量，保留启动崩溃捕获，两轮均少约 142 KiB 模块堆，推迟约 2.2 ms 加载工作 | 收益小，但实际可测；保留，不称作显著常驻改善 |

### 不保留的实验

- 通用 `BoundedHistory` 和曲线快照类已在此前复核撤回，当前源码保持普通日志/曲线数组。
- 当时“未读取日志数组”的最佳微基准不代表实际页面工作方式，不能据此保留复杂数据结构。
- 编辑器/终端已有销毁路径的功能回归不算新优化收益。
- 强制降低 Go 并发、低内存限额、周期性前端强制 GC、销毁后台主界面及裁剪 Windows 工作集均未采用。

## 方法与可复查材料

版本矩阵 32 次运行；字体/按需加载 8 次；订阅与轮询 4 次；连接重绘压力 4 次；语言与压缩 6 次，共 54 次界面运行、216 个私有工作集样本。另有 8 次签名辅助进程运行、独立函数/保留堆实验和 GPU 时间线。主矩阵与专项的代理传输累计 683,081,728 B，逐次 SHA-256 校验，零传输失败；每次配置替换核对均通过。

另外完成一次当前源码的连接历史恢复验收：后台保留 1,000 条，恢复后正常显示原有上限 500 行，近期 20 条记录仍存在，额外传输并校验 103,743,488 B。该次不混入上面的配对性能矩阵。首次恢复验收使用了错误的 CSS 类选择器（camelCase 而非实际的 `connection-row`），因此超时；修正测试定位后第 4 轮通过，失败日志仍保留，未据此修改产品。

统一 Electron 43.4.1、Chromium 150.0.7871.224、1280×800、硬件加速、完整文楷覆盖及相同合成配置。原生窗口始终隐藏；前台由文档可见性模拟，后台使用正式窗口的节流设置。网络仅经过自有回环代理。普通矩阵不包含正式 Windows 特权 relay 或现用客户端，worker 另行保持原有签名、父进程及目录认证测量。

原始目录为工作区 `.codex-tmp/route-individual-audit-20261019/`。主要材料：

- `individual-summary.json` / `summarize.py`：界面及 worker 汇总，完整性检查保留不利结果。
- `release-summary.json`、`releases-*.json`：32 次版本界面对照。
- `startup-*`、`streams-*`、`polling-*`、`history-*`、`catalogs-*`：单项界面对照。
- `validation-current-running-history-background-4.json`：独立的 1,000 条保留、500 行恢复显示及近期记录核对。
- `mechanisms.json`、`retention-*.json`、`schema-*.json`、`state-*.json`、`priority-timer-*.json`：函数、缓存、实际调度和观察器记录。
- `worker-*.json`：签名辅助进程结果；早期目录/管道认证失败日志也保留，没有通过放宽认证解决。
- `module-*.json`、`main-modules-*.json`、`startup-script-sizes.json`：模块加载与脚本图记录。
- GPU 跟踪见单独计时文档。

不同实验的收益不相加，微基准不当作整应用降幅，工作集样本不当作长期上限。此前 107 项界面测试与功能验收不混充为本次新测试次数。本次性能复核阶段没有改动产品逻辑，主要修正测量方法和保留判断；当时现用安装未替换，源码尚未提交、打包或发布。后续打包归档见本文开头。
