# 按需加载阶段的性能测量（2026-10-18）

此文记录本轮中按需加载阶段的单独实验。后续以驻留内存为主的改动和四场景验收见 `MEMORY-PERFORMANCE-2026-10-18.zh-CN.md`，以下局部差值不能作为整轮最终收益。

本轮延续后台空闲优化，保留所有功能及操作入口，主要减少普通界面的初始加载。没有更换框架、关闭活动终端、重载已有页面、丢弃未保存输入或减少日志/故障切换职责。

## 改动

- 终端的原有实现原样移至 `TerminalRuntime.tsx`，由轻量入口首次打开时加载。桌面独立终端和移动端浮层均使用该入口。活动会话的输入、输出、尺寸变化、主题及清理逻辑保持原实现，模块加载后复用。
- 版本说明的原有 Markdown 实现移至 `GitHubMarkdownContent.tsx`，首次展示说明时加载。保留 GFM 表格、任务列表、表情、代码块、原始 HTML 转义及外链属性。
- 发布版界面脚本启用压缩。所有分块均随签名安装包提供，首次使用不需要额外联网。
- 停止服务时，普通界面不订阅仅运行期间可用的节点组；Linux 渲染托盘也按状态订阅组和路由。服务状态流始终保留，启动时自动重新订阅。
- 构建检查实际入口、共享依赖和功能分块：终端/Markdown 库进入任一启动依赖会构建失败；功能分块缺失也会构建失败。字体与图标资源未替换。

## 测量

正式构建以最终 `index.html` 出发，递归读取静态 JavaScript 导入，包含共享脚本，排除首次使用才加载的动态模块：

| 指标 | mxh.14 | mxh.15 |
| --- | ---: | ---: |
| 主界面初始脚本总字节 | 2,484,774 | 777,005 |
| 约十进制 MB | 2.48 | 0.78 |

启动脚本约减少 69%，这是代码加载量，不能解释为内存减少 69%。

另外，使用相同压缩设置的独立隐藏窗口，交替三轮，只比较按需加载库前后的效果。采用真实设置界面、合成接口、相同尺寸和字体，每次稳定等待 30 秒，各取三个内存样本：

| 指标（中位数） | 按需加载前 | 按需加载后 |
| --- | ---: | ---: |
| 渲染器私有工作集（MiB） | 36.86 | 35.10 |
| 设置界面就绪时间（毫秒） | 274.00 | 242.40 |

这一轮额外内存收益约 1–2 MiB，主要收益是减少启动加载与解析。测试主进程的 GC 时点有波动，所以不使用整棵测试进程树的总内存做改善结论。原始记录中，文件协议的 PerformanceResourceTiming 未提供脚本记录，因此该通道记录的零值代表不可测；正式脚本字节数来自实际文件与静态导入图。

功能验收时，首次展示版本说明约 317 毫秒，首次打开终端约 321 毫秒（单次独立测试，含调试观察和就绪轮询）。首次加载期间显示加载状态，已加载模块后续复用。上述不是正式安装实例或 Clash 的直接跑分，也不是端到端 SSH 延迟测量。

## 验证范围

- 228 项回归测试、TypeScript、界面及样式检查通过；正式构建的启动依赖检查通过。
- 真实隐藏 Electron 窗口确认启动没有执行终端/Markdown 分块；打开更新对话框仅加载 Markdown，打开终端才加载终端，随后复用模块。
- 版本说明的表格、表情、外链和 HTML 转义保留；打开/关闭对话框和隐藏/恢复窗口后，未保存输入保留。
- 合成服务状态 IDLE → STARTED → IDLE 时，节点订阅分别为关闭、开启、关闭；不启动任何正式服务。
- 使用真实 xterm 渲染和合成双向接口，验证启动、输入转发、输出显示；隐藏/恢复及切换深浅色后仍是同一会话，导航离开时才关闭。已检查两种主题的隐藏渲染截图。
- 测试使用独立目录，阻断所有外部网络；没有操控用户鼠标或切换现有代理/TUN。

保留上一轮后台辅助进程释放机制。这里的内存差值不可与前一轮直接相加估算当前安装实例，使用过终端或版本说明后，相应库会继续保留以方便再次使用。
