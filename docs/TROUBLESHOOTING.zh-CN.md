# May Route 排错

适用基线：1.14.2-may.26。先记录版本、准确时间、代理运行／停止、规则模式、接管模式、实际入口及刚发生的操作。先只读核对，避免为了复现而改变当前业务出口。

## 规则模式失败、全局成功

1. 检查程序是否实际遵从系统代理或被 TUN 接管；全局模式不改变接管范围。
2. 在连接／日志核对原始域名、重定向下载域名、命中的规则和实际连接链。
3. 核对配置和公开规则是否为当前版本，类别选择组是否选到了错误出站。
4. 分别测试最终资源与中间认证，不用一个主页成功代替整个下载链。

Hugging Face 的模型／数据集下载与交互式 AI 使用是不同分类；学术数据库常需校园出口直连，校园身份子域名与泛数据库域名的优先级也需分别检查。DIRECT 不是学校 VPN。修正权威规则／生成来源后明确加载配置，不只修改运行副本。

## 有业务流量但没有入口监测

查看实际连接链是否穿过支持的入口 selector，或经已配置的固定 `detour`。流量总数、下拉正在查看的组、某节点属于一个组，都不足以证明它经过该组。直接引用具体节点没有 selector 时不会虚构组监测。

核对当前配置、服务状态、事件流和探测入口是否已准备。启动恢复、等待真实活动、组不参与、Direct／停止和真正缺少探测路由分别处理。确认配置不匹配后才按提示重载，不能把初始化等待当作缺配置。

## 很慢但没有切换

先分清手动延迟、核心历史、响应阶段、完整 HTTPS 和业务下载速度。默认探测不测吞吐，单站限速不等于节点整体不可达。

检查该地区是否活跃、当前节点是否参与顺序、上限是否为 0、地区标签是否明确、三目标结果、连续／短窗异常证据及备用是否满足 80% 余量与复核。没有合格备用不会为了「看起来有动作」而切换。长测、睡眠和断采样也不应填补稳定恢复时间。完整策略见[故障切换](PRIORITY-FAILOVER.zh-CN.md)。

## 系统代理暂停恢复／WSL 重复通知

区分 Windows 端点是否仍由 Route 持有、本地 CONNECT 是否健康、其他软件是否设置 PAC／新端点。外来归属时让步是避免争抢的正常保护；预期端点被关闭与被其他程序接管不是同一种恢复。

查看健康日志里与通知相同时间的状态和恢复次数。健康相同设置不应反复写入。WSL 通知表示 Windows HTTP 代理设置变化，不自动证明 WSL 损坏；可检查其他代理软件及实际设置写入来源，不能仅靠关闭通知掩盖变化。

## 更新失败

核对保存后的更新连接，留空是无显式应用代理，输入提示不是已启用地址。指向自身代理端口时核心要运行；显式代理失败不转直连。另核对证书、GitHub 来源、文件大小、版本和签名，不能禁用校验。

取消下载需等待流关闭和部分文件清理；安装器接管后不是同一取消阶段。更新检查显示无可用更新只比较所配置通道和版本，不证明一次失败安装的快捷方式或数据归属已全部正确。

## 快捷方式、卸载与重装

从快捷方式检查目标是否为当前 May 安装，不凭名称判断重复安装。不同用户／全局开始菜单可能有不同入口。先核对目标、应用身份和安装记录；不手工删除来源不明的其他程序入口，也不覆盖未知非空数据目录。

卸载可保留数据；清理工具删除资料后重新安装未必恢复私人配置。保留安装前的备份和签名信息，错误反馈包含安装日志的脱敏阶段，不能只凭「当前能用」推断安装事务完整成功。

## 内存和 GPU／CPU

记录整个进程树而非只看一个进程，分别比较核心、主进程、renderer、GPU 和工作进程。使用相同配置、服务状态、窗口／页面、显示条件、预热时间及流量，报告一段时间的中位数、峰值和增长。

停止服务、清缓存、强制工作集回收或后台窗口少一个，都可能让瞬时数字下降而不代表常态优化。GPU CPU 偏高还需结合绘制、动画、显示状态及时间采样，不能直接把全部占用归给代理核心。既有取舍与撤回结论见[性能审计](PERFORMANCE-AUDIT-2026-10-19.zh-CN.md)和[GPU 测量](GPU-MEASUREMENT-2026-10-19.zh-CN.md)。

## 提供证据

保留 `system-proxy-health.log`、`core-runtime.log`、版本、时间和状态变化。日志为有限轮转，不保证长期保留；在复现后及时截取相关时段。删除地址、Token、用户名、私人域名与配置凭据后再反馈，不上传完整数据库或配置档案。
