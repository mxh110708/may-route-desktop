# Windows 系统代理保持：启停其他客户端时的误提示修复

## 实际证据

以下时间均为 **2026-10-20 北京时间**，来自用户现有 May Route 健康日志；未记录具体代理地址、端口或凭据。

| 时间 | 观察 |
|---|---|
| 18:37:55.772 | 已匹配 Route 的代理开关关闭，进入确认 |
| 18:37:56.803–56.917 | 完成一次恢复，复核归属为 Route |
| 18:38:20.197 | 再次读到关闭，旧版本立即进入暂停并通知 |
| 18:38:22.119–22.234 | 开关已打开、地址匹配，状态正常 |
| 18:38:24.264 | 又出现一次短暂关闭 |
| 18:38:28.044–28.322 | 再次恢复正常；无 PAC 或自动检测冲突 |

上述波动与用户反馈的 Clash 启停时间相符。Clash 日志在 18:37:54 记录刷新系统代理守护及自身系统代理关闭；没有采集进程级注册表写入追踪，因此不把具体每次开关变化归因于某个进程。

本次另用只读方式核对当前用户注册表：开关已打开，HTTP／HTTPS 均匹配 Route，PAC 和自动检测未配置。只读取数据库的恢复检查点一项，其值为 `used`。

根因是旧守护将一次恢复机会锁到用户下一次主动操作：使用后再遇到一次关闭便立即进入暂停，没有像首次恢复那样复核；通知还可能落后于已恢复的实际状态。这与 HTTP 延迟探测无关。

## 修订后的行为

- 地址仍匹配、仅开关关闭时，先连续确认两次，间隔约一秒，再考虑恢复或暂停；不根据一次瞬态立即通知。
- 一次恢复完成后，必须连续观察到 **15 秒归属为 Route 且开关开启**，才重新允许一次自动恢复。节点变化、自动重载和应用重开不直接补充机会；任意相邻观察间隔超过 5 秒，重新计算稳定时间，睡眠不算连续稳定。
- 多次开关变化如果没有完整的正常稳定期，仍不会重复写入。持续关闭且恢复机会尚未重置时，保持暂停，概述页仍可手动恢复。
- 暂停或归属变化需连续观察 **10 秒**才显示系统通知；中途正常、未知、停止或切换接管模式会取消这段通知确认。观察断档不会被算作持续异常。
- 恢复正常或离开该异常状态时关闭当前提示，避免当前通知与状态脱节。同一未恢复阶段只提示一次。
- 真正的其他代理地址、PAC、自动检测设置继续立即避让，绝不自动覆盖；之后即使观察到正常，也不会凭稳定时间解除这类归属保护，仍需 Route 内的明确用户操作。
- RPC 超时／结果不明继续锁定，不能凭之后的一段正常读数重复发出命令。

## 结果持久化与开销

发出恢复请求前记录 `repairing`；收到完成回复后才记录 `used`。应用在请求期间退出，重开后将 `repairing` 视为结果不明，不当作已完成恢复并重新授权。`foreign` 和 `unknown` 保护仍保留。已有的 `used` 记录只有在新的正常稳定期之后才允许恢复，没有直接清空旧数据或重建配置。

继续使用现有两秒本地轮询与一秒确认间隔，不新增网络探测、子进程种类或常驻定时器。稳定期与通知延迟仅使用固定数量的时间戳；检查点只在状态改变时写入。

## 验证范围

本次相关后端回归测试 **116 项全部通过**；TypeScript 类型检查、生产构建及主仓库／Dashboard 差异格式检查通过。

隔离测试覆盖首次恢复、关闭后重新打开的独立事件、启动期间短暂反复开关、持续争夺、稳定后重新允许恢复、持续异常通知及消除、其他地址／PAC 避让、睡眠断档、RPC 超时和请求中退出后的重开。

测试使用模拟归属读数、写入队列、通知回调与可控时钟；未实际启停用户的 Route 或 Clash，未写入当前用户代理注册表或运行版数据库，未安装更新。Windows 原生通知中心的历史记录不作为这些隔离测试的验证结果。
