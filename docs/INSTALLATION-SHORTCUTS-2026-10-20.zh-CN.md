# 安装入口与卸载清理修订

2026-10-20，在 May Route 1.14.2-may.19 重装后确认：静默安装没有桌面入口，启动后开始菜单出现两项同名应用。安装器生成的公共入口标识为 `io.may.route`；通知机制生成的个人入口标识为 `electron.app.May Route`。本机删除重复快捷方式只能解决当时的现象。

Electron 43 的通知激活实现会在当前用户的 Programs 目录确保一个带通知 CLSID 的快捷方式，见固定版本的 [EnsureShortcut 实现](https://github.com/electron/electron/blob/v43.4.1/shell/browser/notifications/win/windows_toast_activator.cc)。因此，单独删除个人入口后，通知初始化仍可能重新生成它。

本次源码修订如下：

- Windows 主进程在自定义构建中设置 `io.may.route`，与安装器保持一致；官方构建继续使用自己的标识。
- 安装入口统一放在当前用户开始菜单，供安装器与 Electron 通知机制共同使用。应用二进制和服务仍采用机器级安装；其他 Windows 用户首次运行时，由 Electron 注册其个人通知入口。
- 应用内更新由 SYSTEM 服务在请求用户的会话中启动安装器。快捷方式目录按该会话的用户令牌读取，遵循桌面重定向；不使用 SYSTEM 的个人目录。安装完成后的启动入口使用同一解析结果。
- 安装时仅移除指向本次安装 EXE 的公共重复入口；同名但指向其他应用的入口保留。个人入口发生冲突时停止处理，避免覆盖其他文件。
- 全新静默安装默认创建桌面快捷方式，并支持标准的禁止创建桌面入口选项。已有桌面入口时只刷新原入口，不额外创建公共副本。自动更新保留用户已删除桌面入口的选择；交互安装继续提供完成页选项。
- 卸载核对快捷方式的实际目标，清理本应用的个人及公共开始菜单、桌面入口。同名的其他应用快捷方式保留。
- 无迁移事务时回收空的安装器状态目录。选择删除应用数据时，仅删除已经为空的供应商注册表父键和安装器目录；其他产品注册项、迁移证据和非空目录保留。

回归检查使用临时目录中的真实 Windows `.lnk` 文件，覆盖首次创建、重复入口修复、卸载、同名外部入口保护和路径越界拒绝。Windows 应用标识检查执行源码中的真实启动分支，并与两套安装配置对照。测试不操作现用应用或鼠标。

这些改动随 `1.14.2-may.20` 发布。现有 `1.14.2-may.19` 可在应用内检查更新；更新安装器会修订开始菜单入口并保留现有应用配置、字体和故障切换设置。更新保留用户已删除桌面入口的选择，不会强制重新添加桌面快捷方式。

本地验证：184 项桌面回归及类型检查通过；13 项真实快捷方式及用户目录检查、4 项存储清理检查通过。另在一次性 SYSTEM 任务中执行相同的本地令牌与 Shell 目录解析代码，结果与当前用户的 Programs、DesktopDirectory 相符，并确认拒绝会话 0；任务已移除，未运行应用安装器。使用原有解包载荷编译了包含新安装脚本的隔离 NSIS QA 包，编译通过，未执行此包。存储检查直接载入同一份源码中的函数并测试真实目录；安装器 CLI 对 ProgramData 固定路径的限制保持有效，没有为测试放宽该限制。
