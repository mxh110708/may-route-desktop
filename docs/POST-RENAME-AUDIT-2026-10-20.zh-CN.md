# 改名后代码审计

本次复查 `1.14.2-may.19`、`.20` 及安装错误修复。目标是保持单一 May 身份，删除无实际 May 使用场景的旧路径导入，不按关键词删除正常的数据保护与业务功能。

| 项目 | 结论 | 证据与处理 |
| --- | --- | --- |
| May 安装 GUID、appId、服务、管道、数据流与目录 | 保留 | 产品的持续身份；实际安装和运行都使用 May，没有旧 MXH 身份回退。签名身份与 GitHub 账号不改动。 |
| 品牌专用开机启动迁移 | 已移除 | `311bfce` 已取消该调用，当前源码没有 `brandLoginItem` 模块或调用；新安装不接管旧品牌启动项。 |
| Windows 应用标识与个人开始菜单入口 | 保留并修正 | Electron 通知机制会创建个人入口。实际重复现象已确认；运行时、安装器使用同一 `io.may.route`。`.20` 的脚本宿主遗漏导致安装收尾失败，不能视作完整解决。 |
| 原生 PowerShell 宿主 | 保留 | 真实 32 位 NSIS 宿主稳定复现 Program Files 被解析为 Program Files (x86) 的误判；改用原生宿主后通过。普通用户与 SYSTEM 下均验证，同名其他应用仍被拒绝，没有针对失败状态的兼容分支。 |
| 首次静默安装桌面入口、卸载归属核对 | 保留 | 正常安装功能；更新保留用户删除桌面入口的选择，只整理属于当前安装的快捷方式，不按品牌名删除陌生入口。 |
| `may-route-legacy` 导入路径和开关 | 删除 | May 首个正式安装已使用布局版本 2，没有正式版本生成该目录。删除机械改名后保留的虚构旧目录、查找函数和调用开关。 |
| 自定义数据目录搬迁、所有权、事务恢复 | 保留 | 用户仍可更改数据目录，卸载保留数据后可重装。真实目录检查覆盖标准目录与自定义目录互转、外部归属拒绝、空状态目录回收及恢复证据保留。 |
| 数据库、启动参数和故障切换设置格式转换 | 保留 | 来自改名前的功能与上游数据格式演进，不查询旧品牌目录、旧服务或旧安装；不能随命名清理删除正常配置读取能力。 |

修复仅选择正确脚本宿主，没有放宽快捷方式归属判断，没有自动删除冲突入口，没有增加旧品牌数据自动导入或升级失败识别代码。测试代码的 NSIS 可执行文件只操作临时目录，不进入应用包。

May Route 的正常更新沿用当前 May 安装身份和配置；旧 MXH 安装不由新程序接管。实际安装结果在发布验收时另行记录，不以编译或单元测试代替安装结果。
